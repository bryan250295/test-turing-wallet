02 · Protocol concept change

核心改变：从“信任 minter”转为“合约验证 proof”

旧 Concept：Custodial / trusted-minter bridge

资产真实性与 mint 决策主要由 backend/operator 的 custody、API 检查和授权账户保证。

用户 TBC FT发送到每笔订单的 custody address
›
Backend custody持有/恢复加密 custody key，等待 confirmations
›
Trusted minteroff-chain 判断通过后调用 mint
›
BridgeWrappedFT只检查 caller 是否为 minter
Owner / Admin authority可以暂停合约，并更换 minter；控制权属于 backend/operator 管理的角色账户。
Contract 不验证 TBC proof合约本身不知道 custody deposit 是否真实；它信任被授权 minter 的判断。
→

新 Concept：Proof-backed mint authorization

Backend/relayer 只负责取得资料、构建 proof 和支付 gas；是否 mint 由 immutable Gateway rules 决定。

TBC v2 deposit绑定 destination Gateway 与 reserve controller
›
Proof verifiersheaders、Merkle、transition、signature、prefix
›
Proof Gateway验证全部 gates、finality 与 replay protection
›
WrappedFTV2只有 Gateway 可以 mint
没有 trusted minter任何 relayer 都可以提交，但没有人能绕过 proof；relayer 是运输者，不是 mint authority。
没有 owner / admin 后门Gateway 与 WrappedFTV2 没有 alternate minter、暂停 key 或任意 mint 权限。
目前迁移状态旧 custodial flow 仍保留并服务既有 learning receipts；新的 proof-backed Testnet-v2 verifier、Gateway 与 wrapped token 已全部部署。第一笔 100 MT Bridge Covenant deposit 已由 Turing Wallet 签名并广播，但仍须完成入块、6 confirmations、header relay、Merkle/FT proof 与 Gateway mint，才算端到端完成。

信任模型Custody + trusted minter；owner 可暂停及更换 minter，合约不验证 TBC proof。新 deposit 已绑定 Gateway/recipient/controller；最终 mint 尚未发生，但不再交给 trusted minter 决策。无 owner / alternate minter；Gateway 在 EVM 验证 header、Merkle、transition、signature、prefix 与 replay。

一次性 setup gas

部署 verifier 与 Gateway 的费用只发生在管理员 setup，不会让每个 bridge 用户重复支付。由于 HyperEVM Testnet block gas limit 为 3,000,000，各组件需要分开部署。

每次 transfer gas

仍存在 source network fee、必要的 header relay 与 Gateway mint gas。自动化不会令 gas 消失，而是减少重复动作、共享 header 成本，并把 gas payer 改为 operator。

! Production 仍未解决
